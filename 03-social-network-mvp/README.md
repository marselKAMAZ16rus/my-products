# Reef

Reef — самостоятельная социальная сеть для общения в кругу друзей с развёртыванием на собственном сервере.

## Возможности

- Вход по одноразовому коду из электронной почты и регистрация по приглашениям.
- Профили, друзья, социальный граф и управление аудиторией публикаций.
- Лента, фотографии, короткие видео, комментарии, опросы и личные сообщения.
- Web Push, уведомления и QR-коды приглашений.
- Хранение данных на собственном сервере, миграции SQLite и обновление с резервным копированием.

## Технологии и архитектура

| Компонент | Реализация |
| --- | --- |
| Сервер | Node.js 24, HTTP, ES modules |
| Данные | SQLite (`node:sqlite`), SQL-миграции |
| Интерфейс | HTML, CSS, JavaScript, Service Worker |
| Почта | Nodemailer, SMTP |
| Развёртывание | Ubuntu 24.04, Nginx, systemd, Let's Encrypt |

- `app.mjs` — HTTP-сервер и интеграция компонентов.
- `auth.mjs` — аутентификация по почте.
- `worker.js` — API, бизнес-логика и встроенные клиентские ресурсы (сборка).
- `storage.mjs` — SQLite и файловое хранилище.
- `push.js` — Web Push.
- `drizzle/` — миграции и снимки схемы.
- `install.sh`, `update.sh` — установка и обновление.

## Быстрый старт на сервере

Понадобятся Ubuntu 24.04, домен, направленный на сервер, открытые порты 80/443 и SMTP-аккаунт Mail.ru с паролем приложения. Из корня репозитория на выделенном сервере:

```bash
sudo mkdir -p /opt/reef
sudo cp -a . /opt/reef/
sudo bash /opt/reef/install.sh
```

Установщик меняет системную конфигурацию, поэтому не запускайте его на рабочей машине без проверки. Введите собственные настройки при запросе. Первый подтверждённый вход создаёт аккаунт владельца. `reef.example.json` — только пример структуры конфигурации; не используйте его заглушки в рабочем окружении.

## Конфиденциальность

Репозиторий содержит код и схему базы, но не рабочую базу, пользовательские медиа или конфигурацию сервера. Не публикуйте `/etc/reef/reef.json`, `/var/lib/reef/` и резервные копии. Ключи и пароли создаются или вводятся при установке.

## Эксплуатация

### Reef на Ubuntu 24.04

Требуется Node.js 24 LTS. Установщик проверяет официальный архив Node.js по SHA-256, устанавливает зависимости, спрашивает настройки в терминале, проверяет SMTP, настраивает Nginx, HTTPS Let's Encrypt и systemd.

Новая база создаётся автоматически в `/var/lib/reef/reef.sqlite`. Фото хранятся в `/var/lib/reef/media`. Старые данные из Sites не загружаются. Установщик не удаляет существующую базу при повторном запуске.

Пароль приложения Mail.ru вводится скрыто. Настройки — `/etc/reef/reef.json`, доступ только root. Письма отправляются от имени SMTP-ящика; коды, пароли и сессионные ключи не записываются в журнал.

Владелец входит по `REEF_OWNER_EMAIL`. Первый подтверждённый код создаёт владельца. Остальные аккаунты создаются только после приглашения и подтверждения почты. Код действует 10 минут, до 5 попыток; повторный запрос — не чаще минуты. Вход сохраняется на 30 дней. SMTP бесплатного ящика имеет ограничения провайдера, доставка не гарантирована.

После смены домена все устройства должны снова подключить пуши: разрешения браузера привязаны к домену.

Проверка сервиса: `systemctl status reef --no-pager`. Журнал: `journalctl -u reef -n 50 --no-pager`. Проверка почты: `node /opt/reef/smtp-check.mjs`.

Перед обновлением сохраните `/etc/reef/reef.json`, сделайте согласованную копию SQLite командой `sqlite3 /var/lib/reef/reef.sqlite ".backup '/root/reef-backup.sqlite'"` и скопируйте `/var/lib/reef/media` в отдельное хранилище. Сам VPS не является резервной копией.

## Обновление без сброса данных

Новая сборка включает `update.sh`. Загрузите архив `reef-update.tar.gz` на сервер, извлеките только этот скрипт и запустите от root с путём к архиву. Скрипт подготавливает зависимости до остановки службы, сохраняет SQLite и настройки в закрытом `/var/backups/reef/<дата>`, меняет код и проверяет запуск. При ошибке восстанавливает предыдущий код и базу. Фотографии остаются в `/var/lib/reef/media`; настройки SMTP и ключи уведомлений не меняются. Резервные копии доступны только root, их не следует размещать в каталоге сайта.

Обновление 14 ноября: новые регистрации по приглашению автоматически связывают друзей; обычные заявки требуют согласия. Исправление старых приглашений касается только первоначальных заявок, созданных при регистрации.

## Фото, комментарии и видеоквадратики

Фото сохраняют весь кадр; обрезка включается отдельно. Комментарий может содержать одно фото или видеоквадратик. Доступ к вложению проверяется через публикацию; ограничения комментариев проверяются сервером независимо от интерфейса. По умолчанию могут комментировать все, кто видит пост. Автор может выбрать круг, отдельных исключённых пользователей или оставить комментарии только себе.

Короткие видео записываются/сжимаются в браузере через MediaRecorder и canvas: 480×480, 24 кадра/с, целевой видеобитрейт 600 кбит/с, звук 64 кбит/с, до 60 секунд и до 8 МБ на файл. Требуется актуальный браузер с MediaRecorder и canvas.captureStream. Сжатие выбранного файла занимает примерно его длительность; пользователь видит прогресс. Кодеки выбираются из доступных WebM/MP4. Настройки SMTP при обновлении не меняются.
